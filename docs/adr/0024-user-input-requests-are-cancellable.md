# User input requests are cancellable

Mistle **User input requests** must always let the user cancel instead of answering, and cancellation is a first-class request response rather than an ordinary answer value. Cancellation returns control to the active runtime request without treating the choice as a full turn interruption; each runtime adapter that exposes `tool/requestUserInput` must translate cancellation to a real runtime cancellation or surface an explicit unsupported-cancellation error. A runtime SDK may require a transport-specific negative permission response, such as Claude Code `deny`, but that transport remains an implementation detail of user input cancellation and must preserve the cancellation message. This rejects synthesizing empty answers, treating cancellation as an ordinary runtime approval decline in Mistle's shared contract, stopping the whole turn, or allowing per-request opt-out because those alternatives either lose user intent or can leave the user trapped in a pending question.
