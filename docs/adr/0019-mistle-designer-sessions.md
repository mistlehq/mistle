# Mistle Designer uses one-to-one sandbox-backed sessions

Mistle Designer uses durable **Mistle Designer sessions** backed one-to-one by a sandbox instance with the `designer` purpose and a **Mistle Designer base image**, while durable configuration is written into real product resources such as draft **Sandbox profile versions** instead of a separate design-plan resource. Designer sessions currently persist the user's initial prompt and route-backed **Designer canvas tabs** as workspace state; future chat history can carry **Designer recommendations** rather than separate recommendation records. This keeps the guided setup workspace independent from the configured agent's eventual **Agent runtime**, avoids duplicating sandbox profile configuration in a separate design model, and still lets Designer orchestrate integrations, provider configuration resources, triggers, publish, and launch with explicit user approval for side effects.

Designer sessions may read and refresh scoped **Provider configuration resources**, and may perform approved itemized **Provider configuration changes**, but the first pass does not require detailed durable activity history for those provider-side changes. Integration authorization and trigger review continue to use existing route-backed product flows in **Designer canvas tabs**, with completion detected from control-plane resource state rather than page-to-agent callbacks.
